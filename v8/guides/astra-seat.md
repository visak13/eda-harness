# astra-seat — GPT-6 Astra as a 1:1 fleet seat (epic-6a8a6020fd · s-e1260012b9)

Owner words: "use GPT 6 Astra with any harness out there we can to add Claude Code like monitor and cron tools … behave exactly the same". Design: board doc design-97ca02e989 (this guide carries its survey, terms and control cards verbatim so the record is readable without the board) plus the spike evidence. Parity reference: `guides/harness-parity.md`.

## 1. The fidelity requirement, decomposed (what "exactly the same" needs from a harness)
| need | Claude Code behaviour | harness primitive required |
|---|---|---|
| N1 tool set | `Monitor{command|ws,description,persistent,timeout_ms}`, `TaskStop`, `CronCreate{cron,prompt,recurring,durable}`, `CronList`, `CronDelete` with fixed description/result strings | client-registered tools, in-process, long-lived background work allowed |
| N2 idle wake | a Monitor line or a due cron becomes a new user turn only when the REPL is idle | idle signal + "deliver when idle" primitive |
| N3 mid-turn attach | a Monitor line during a turn is attached to the model's NEXT tool result (any tool) | a hook that can mutate/append to any tool result |
| N4 cron rules | 5-field local cron, recurring/one-shot, deterministic jitter, 7-day expiry, session-only, fires only when idle | harness-owned scheduler + N2 |
| N5 boot | role card as first input, edp8 MCP (streamable HTTP + `X-Participant/X-Token` headers), resume | system/developer prompt injection, MCP client with headers, session resume |
| N6 fleet | spawn/alive/kill/pid/last-output from the pool; `EDP_HARNESS` park semantics | headless start, machine-readable events, stop |

## 5. Recommendation and decision
**Primary: Pi.** The only harness whose documented API covers N1–N4 without adaptation: `registerTool` (N1), `sendMessage(deliverAs:"followUp")` = "delivered only when idle" (N2, N4), `tool_result` content patch on any tool (N3), `agent_settled`/`isIdle()` (N2), JSONL RPC from Python (N6), Astra on both auth paths since 0.85.1, MIT, an OpenAI-named harness. Its one gap is N5's MCP client: Pi has none, so the edp8 extension bridges the board's MCP over streamable HTTP with headers (moderate, spike-verified). [Astra: Pi first]
**Secondary: OpenCode.** Native MCP + headers, pool backend exists, `tool.execute.after` (N3), `session.idle` (N2); weaker on N2/N3 because a busy session rejects prompts (buffer-then-flush in the plugin) and there is no steer.
**Fallback: Codex app-server** — permitted and native, but N3 only for its own dynamic tools; native shell/patch results can only receive `PostToolUse additionalContext` developer text, so "attached to the next tool result" is not literally met. [Astra]
**Conditional experiment: route A1** (Claude Code + local proxy + OpenAI API key). Literal parity by construction (N1–N4 are Claude's own code), Anthropic-unsupported but not prohibited, OpenAI-permitted. A half-day spike, because translation fidelity (tool schemas/ids/streaming/thinking/compaction) and feature leakage to api.anthropic.com are unproven, and because the owner must accept "unsupported" as a production posture. [Astra: conditional]
**Auth for a resident seat: OpenAI API key, not ChatGPT OAuth.** OpenAI's auth doc routes programmatic/unattended workflows to keys; an always-on seat with 30-min heartbeats is that. ChatGPT OAuth is acceptable for spikes and the human-present drill only, with the owner's explicit acceptance. Cost at Astra API pricing is an owner decision (G1).
**Parity is proven, not asserted:** `guides/harness-parity.md` captures Claude's tool schemas/texts/envelopes and MEASURES the unstated rules from a live seat's session JSONL (the model-input boundary); `scripts/parity_oracle.py` replays one scripted sequence through a Claude seat and the Astra seat and diffs at that boundary, under a controlled clock/seed for timing. [Astra]
**Text-copying exposure:** byte-equal tool descriptions in a non-Anthropic harness are an IP question the terms do not settle; the owner accepts it at G1 or the descriptions are paraphrased (then "exactly the same" narrows to behaviour + schemas).
