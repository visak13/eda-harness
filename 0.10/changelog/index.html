    Changelog¶

    All notable changes to Heronry are recorded here. The format follows Keep a Changelog, and versions follow Semantic Versioning. Every release is on the releases page.

    Unreleased¶

    [0.10.8]¶

    This release fixes what qa found in the 0.10.7 candidate.

    Upgrading¶

    • From 0.10.5, 0.10.6 or 0.10.7: run heronry update --release-url <0.10.8 release folder> --previous-url <your current release folder>, or run install-heronry.cmd from the 0.10.8 release folder. Restart open seats, and reload any open board tab.
    • From 0.10.0 to 0.10.4 (preview builds), desktop app: run install-heronry.cmd from the 0.10.8 release folder (double-click it, or type it in a terminal). It checks every file against SHA256SUMS, stops the code server and the services, installs the .msi and starts Heronry again.
    • From 0.9.x, desktop app (the .msi): by hand, this once. 0.9.x's heronry update refuses a desktop install ("the desktop bundle updates through its installer"). From 0.10 on, heronry update and the tray's Check for update install the new .msi themselves.
    • heronry stop all --force: stops every service and takes the seats offline. Running codex seats are processes of the installed heronry.exe and would lock the install folder.
    • Run Heronry Desktop-0.10.8.msi: double-click it, or msiexec /i "Heronry Desktop-0.10.8.msi". It upgrades in place; your board data and settings stay. If Windows still shows a "files in use" dialog naming Heronry, keep its default, Automatically close applications: it is safe.
    • heronry start, or open Heronry Desktop.
    • From 0.9.x, command line (install.ps1 / install.sh): heronry update.
    • The first start refreshes the agent home (role cards, skills, hooks, guides) and merges the new model catalog into yours. A file you edited is kept, with the new version beside it as <file>.new.
    • After an update or a board restart, a Claude Code session that was open through it may have lost the edp8 tools: run /mcp and pick Reconnect for edp8. Seats reconnect on their own.

    Fixed¶

    • Seat tokens: the pool's session list no longer shows each seat's board token or provider keys. The pool answers on this computer only, but any program running here could read them.
    • Quiet wakes cost one model turn, not two: a seat with nothing to do now ends a heartbeat with one short line. An empty reply made Claude Code prompt the seat a second time.
    • install-heronry.cmd from PowerShell 7: started from a PowerShell 7 terminal, it stopped at the checksum step with "Get-FileHash is not recognized". It now checks the installer the same way from any terminal.
    • Start: a second heronry start leaves a running MCP server alone. It used to stop and restart it, which dropped the edp8 tools from open Claude Code sessions until they reconnected.
    • EDP Chat in Restricted Mode: it loads in a folder you have not trusted yet. Git features stay off until you trust the folder.
    • Update: after an update, heronry start restarts a code server that still serves the previous EDP Chat, so the new version loads without a manual step, even when the update ran from an older heronry.
    • heronry update --help: prints usage and runs nothing; it used to run an update check.
    • Board on a phone and desktop: the first Mark as requirement no longer moves the page by 2 px; Admin → Seats & models and Library → Tickets show one card per row on a phone, so model ids and titles never break mid-word; Open topic stays on one line; each epic row reads "No criteria yet" or "N/M criteria passed" once; a guest no longer sees Quick task and New epic.
    • More phone layouts: Design → Every move, Admin → Remote access → Every check and the Integrations harness table show one card per row on a phone. The sign-in card shows no error until a sign-in fails, and never pre-fills a participant. The request-access role reads Guest or Member, with what a guest sees under it.
    • Heronry Chat: it opens on its first start, so a new profile no longer hides it behind "…". The Inbox shows the sender's role, and in a narrow sidebar the tabs stay on one row with ‹ › to scroll.
    • Remote access: host names and file paths no longer break at a hyphen; a failed sign-in says so once.
    • Clipped controls:
    • the Code page header at phone width;
    • Restart in Admin → Services at desktop width;
    • the Admin → Teammates and agent-token tables at phone width, which now show as cards;
    • the Design hook rows at phone width.
    • Admin: a refused admin action shows one plain line, never internal header names, and Teammates no longer shows the setup note under the first owner.
    • Mark as requirement: the first mark on an epic no longer pushes the conversation down. The open-requirement count shows in the header's Needs attention field.
    • Close alerts: starting a seat with a first instruction no longer alerts the architect that the seat is closed.
    • Criteria: a criterion re-pointed to a new report shows that report's version, not the old one's.

    Changed¶

    • Text-fits check: it runs on realistic data (teammates, services, a running code server) and opens every tab of every page.

    [0.10.7]¶

    This release fixes what qa found in the 0.10.6 candidate and what an independent audit found in its wake plane.

    Upgrading¶

    • From 0.10.5 or 0.10.6: run heronry update --release-url <0.10.7 release folder> --previous-url <your current release folder>, or run install-heronry.cmd from the 0.10.7 release folder. Restart open seats so they pick up the new wake listener, and reload any open board tab.

    Fixed¶

    • Reload banner: it compares release versions, so it no longer shows on every page after an update, and Reload clears it.
    • Wakes:
    • a hint that a closed seat left a message is never dropped;
    • a long message keeps its whole text, and one cut by the board is fetched in full whoever it is addressed to;
    • a seat that closes, resumes and closes again wakes the architect each time;
    • lines that arrive together, such as a close and its hint, arrive as one turn.
    • Close alerts: a message is not alerted twice when it sits on another ticket, nor when the seat's own closing post names it.
    • Phone layout: no word breaks mid-letter, the Epics list title shows, Library and Admin tabs wrap so every tab is visible, placeholders fit their fields, and an open composer never hides a message once the page is scrolled.
    • Mark as requirement: the popover closes, and "Requirement marked." shows in the composer's status line. Nothing on the page moves and nothing is covered.
    • Epic header: it shows the architect's seat state ("Architect · running", "closed", "not started") the same way the Seats page does, and updates as soon as the seat closes.
    • Help: plain words throughout, Title is described as editable, and no empty headings.
    • Document page: one Show panel button, the back link names the epic, and the reader uses the page width.
    • EDP Chat: it shows in Restricted Mode, with git features off until the folder is trusted, and its tab row wraps.
    • Wording: plain words for the spawn result, the notify line, pinned counts, the ticket placeholder and the sign-in page, and no internal ids in captions.

    Added¶

    • Text-fits check: an automated walk of every page at desktop and phone width fails on clipped, overflowing, off-screen or covered text and controls, and on layout that shifts when you mark a requirement.

    [0.10.6]¶

    This release fixes what qa and an independent audit found in 0.10.5.

    Upgrading¶

    • From 0.10.5: run heronry update --release-url <0.10.6 release folder> --previous-url <0.10.5 release folder>, or run install-heronry.cmd from the 0.10.6 release folder. Restart open seats so they pick up the new wake listener. Reload any board tab that was open; 0.10.6 tabs will prompt you to reload after future updates.

    Fixed¶

    • EDP Chat signs in again. The board URL is now written where code-server reads it (Machine settings), and the extension defaults to port 19400.
    • Wakes:
    • a seat with the edp-wake mod no longer arms a second listener;
    • an addressed message arrives with its full text;
    • a seat is not woken for its own actions;
    • one seat close arrives once, not twice.
    • Close alerts: one seat close gives the architect one alert, listing only the messages the seat never read. It used to send one alert per message.
    • Quote popover: the note gets its own row, Quote is the main button, Mark as requirement is secondary, and the popover never covers the selected text, at desktop or phone width.
    • Epic page seats: each seat shows its state, a live seat offers Close and a closed one Resume, and the header and the Assign dialog agree on the assignee.
    • Gates: the retired acceptance gate is gone from the decision form, and any acceptance gate left open is closed at board start.
    • Help and glossary: written in plain words, with no internal ids, API paths or jargon. A test enforces this. The glossary adds Requirement and fixes Scope.
    • Phone layout: the process chips, the help button, the composer (one line until tapped), the loading placeholders and the help sheet.

    Added¶

    • Reload banner: a tab left open across an update tells you to reload.
    • edp-wake mod tests: they run from the repo with one command, uv run --no-sync python scripts/test_wake_mod.py, whatever your Claude Code settings.
    • qa role card: qa walks every screen a person sees in the installed app with Playwright, at desktop and phone width, judges the layout, and cites a screenshot for every pass.

    Changed¶

    • Subscription audit: it covers every board hint, and the list of hints is taken from the source.
    • Code-guards inventory: it matches the design's kept list.

    [0.10.5]¶

    You talk to the architect in chat. The board no longer keeps a "Needs you" list for you; it records requirements, hints the architect, and pages you only for what no seat can heal.

    Upgrading¶

    • From 0.10.4: run install-heronry.cmd from the release folder (double-click it, or type it in a terminal); it checks every file against SHA256SUMS before it installs. Seats the pool starts after the update load the edp-wake mod (Claude Code 2.1.287 or later); a seat that was already open keeps its Monitor until it restarts.

    Added¶

    • Mark as requirement. Select words in any message and press the second button on the quote card. No message is sent: the board records the quoted words as a requirement of the epic, and the epic cannot finish while one is open. The architect closes each one by linking it to a criterion or to a section of the design (requirements, requirement_link). Guests can mark too.
    • Close on the Seats page and the epic page ends a live seat's shell, recorded as "closed by owner" (or "closed by architect"). It is a clean close: no crash notice and no new checker. An architect can close only seats on its own epic, and a caller can't put words in the close reason that name who closed it.
    • Claude Code seats wake through the edp-wake mod instead of a Monitor they re-arm: one turn per real event, carrying the message's full text, and one quiet tick every 30 minutes.
    • A read-only docs mirror: the board writes every doc to <agent-home>/docs/<scope>/<id>.md in the same step as the database write, so seats can Read and grep it. Edits still go through doc_edit, which now takes old_string / new_string / replace_all like a file edit; doc_create and doc_update also accept body.
    • The site has a Using Heronry guide with screenshots of every main screen: the conversation, quotes from messages, designs and code, attachments, the Work drawer, the design beside the thread, Seats, VS Code on the same thread, guests and a phone. The screenshots come from a made-up demo project on a throwaway board, never real data. npx playwright test -c playwright.guide.config.ts in v8/web regenerates them all.

    • Reference → MCP tools now documents every tool's input and output. Each argument has a plain explanation, and each tool shows a real example call and reply, captured on the same made-up demo board. The explanations live in a docs-only file, so the tool descriptions agents load are unchanged. npx playwright test -c playwright.guide.config.ts tools in v8/web recaptures the examples.

    • The architect or the owner can retype an epic or a story (ticket_update work_type=…), and its pending criteria move to the checker the new type calls for. A product-docs story typed "knowledge" by mistake went to the epic's sme, which is meant for research; retyped to feature, it goes to qa. Verdicted lines and a checker the owner set by hand stay as they are, and each move is recorded on the ticket.

    Changed¶

    • The board hints instead of acting. When an epic moves to in_review the architect gets a qa_available hint and starts qa itself; the board spawns no seat and opens no acceptance gate. Every pool event (a seat that crashed, stalled, closed or resumed) goes to the epic's architect, who heals it. Only when the epic has no live architect does the board write you a plain chat message, and a second one when the seat is running again.
    • Gates are cut to two: design sign-off (the Approve button) and scope. Proof of concept, demo, adversarial and budget are the architect's calls, told to you in chat. A reply of yours in chat lifts the story cap (ticket_create cap_lift_message=<your message id>; the board checks the message is yours).
    • Rules advise, they don't block. Only state transitions, who may approve, safety, evidence, doc versions and the caps refuse a call; other guards (a task without serves, a blank gate note, more than five tasks on a story) return a hint. Each role's tool bundle holds only the tools that role needs.
    • A message that reaches a seat just as it closes is never lost: when a seat closes, the architect is hinted for every message addressed to it or @mentioning it during that run that the seat neither replied to nor resolved.

    Removed¶

    • The Needs you and Waiting on you lists, the asks ledger and the asks / ask_triage triage flow. Requirements and chat replace them.

    Security¶

    • An access request from the sign-in page now makes the person a guest unless the admin chooses otherwise. Before, the request form asked for member access by default, and Approve granted whatever the requester picked, so a stranger approved with one click became a full member. The request form now defaults to Guest, and the Approve row in Admin → Teammates has its own access picker set to Guest. A person can only be a guest or a member (agent roles are refused for people), and a guest can't be approved as an admin.

    Fixed¶

    • An installed Heronry now installs EDP Chat, and updates it, in its VS Code (heronry start code). Before, only a source checkout did: the installer's wheel carried neither the extension nor the pinned extension list, so an installed code-server came up without EDP Chat and without the pinned Python extensions. The wheel now carries both, and the release builds refuse to make a wheel without the extension.
    • A seat resumed from Seats (or by the board, for a checker) comes back with its board tools. Before, the board rotated the seat's secret on every spawn attempt, and the pool's resume then restarted the shell with the old one from its first spawn, so every board call was refused and the seat sat without tools. Resume now hands the pool the seat's current secret, and a spawn the pool refuses no longer rotates it.
    • The VS Code extension in the bundled code-server now connects to the board's actual port. Its built-in default is :9400, but the board's ports move when the default ones are taken (19400 on a typical desktop install). heronry start code now writes edp.boardUrl from the running board, and keeps a remote board you signed in to.
    • install-heronry.cmd keeps the installer in data\updates\<version>\, so the next heronry update can roll back to it. Without it, the update refused with "couldn't secure the installed version's MSI for a rollback".

    [0.10.4]¶

    The first update run by 0.10.3's updater: heronry update follows the update in the terminal to its result.

    Upgrading¶

    • From 0.10.3: heronry update, for the desktop app and the command line alike. Typed in a terminal, it prints each step there through to the result (installed, rolled back with its reason, or failed with the one recovery command) and returns 0 only when it installed; from the tray, a "Heronry update" window shows the same steps.
    • From 0.10.2, command line (install.ps1 / install.sh): heronry update. The shell prints each step until it hands the install to the helper; heronry status shows 0.10.4 when it is done.
    • Desktop app (the .msi) from 0.10.0, 0.10.1 or 0.10.2: run install-heronry.cmd from the release folder (double-click it, or type it in a terminal). It checks the .msi against SHA256SUMS, stops the code server and the services, lists anything still running from the install folder and offers to stop it, installs with the Windows Installer's progress bar, starts Heronry (and the code server if it was running) and shows heronry status and the version. Every step is printed and the window waits for a key at the end; install-heronry.cmd --check only checks and changes nothing. heronry update cannot do this hop: 0.10.2's own updater runs it and its helper dies at its first import in the bundle (see 0.10.3). From 0.10.3 on, heronry update typed in a terminal follows the update in that same terminal until the result (installed, rolled back, or failed with the one recovery command), and its exit code says which. A per-app firewall (for example Bitdefender) may treat the updated heronry.exe as a new program and block its downloads (WinError 10013 from heronry start code); allow heronry.exe in the firewall's application rules.
    • From 0.10.0, 0.10.1 or 0.10.2, desktop app (the .msi), without the script: by hand, this once. heronry update cannot do this hop: it runs the installed version's own updater. 0.10.2's dies at its first import; 0.10.0's and 0.10.1's can hand msiexec the install folder in a form msiexec refuses when the folder name has a space (the default Heronry contributors\Heronry Desktop does), so it rolls back with "msiexec exit 1639" and Windows shows the msiexec usage box. From 0.10.3 on, heronry update works. The steps:
    • Close every seat window.
    • heronry stop code.
    • Stop each feed monitor by its pid: list them with Get-CimInstance Win32_Process | ? { $_.CommandLine -like '*edp8.feed_driver*' } | select ProcessId, then taskkill /PID <pid> /F for each.
    • heronry stop all --force.
    • In PowerShell, in the folder with the .msi, run exactly (it waits until the installer is done): Start-Process msiexec -Wait -ArgumentList "/i `"$PWD\Heronry Desktop-0.10.4.msi`" MSIINSTALLPERUSER=1 ALLUSERS=2 INSTALLFOLDER=`"$env:LOCALAPPDATA\Programs\Heronry contributors\Heronry Desktop`" /l*v `"$env:TEMP\heronry-0.10.4-msi.log`"". Typed as a plain msiexec … INSTALLFOLDER="…" line, PowerShell 5.1 re-quotes the whole token, the form msiexec refuses with 1639. It upgrades the per-user install in place (a different scope or folder would install a second copy); your board data and settings stay. If Windows shows a "files in use" dialog naming Heronry, keep its default, Automatically close applications.
    • heronry start, or open Heronry Desktop.
    • heronry start code.
    • Resume each seat from the board, and check that the board shows one live window per seat; close any extra.
    • From 0.9.x, desktop app (the .msi): 0.9.x's heronry update refuses a desktop install ("the desktop bundle updates through its installer"), so this one upgrade is by hand. From 0.10 on, heronry update and the tray's Check for update install the new .msi themselves.
    • heronry stop all --force: stops every service and takes the seats offline. Running codex seats are processes of the installed heronry.exe and would lock the install folder.
    • Run Heronry Desktop-0.10.4.msi: double-click it, or msiexec /i "Heronry Desktop-0.10.4.msi". It upgrades in place; your board data and settings stay. If Windows still shows a "files in use" dialog naming Heronry, keep its default, Automatically close applications: it is safe.
    • heronry start, or open Heronry Desktop.
    • From 0.9.x, command line (install.ps1 / install.sh): heronry update.
    • The first start refreshes the agent home (role cards, skills, hooks, guides) and merges the new model catalog into yours. A file you edited is kept, with the new version beside it as <file>.new.
    • After an update or a board restart, a Claude Code session that was open through it may have lost the edp8 tools: run /mcp and pick Reconnect for edp8. Seats reconnect on their own.

    Fixed¶

    • When the update helper ends without a result, the terminal names the real update.log path instead of a literal %LOCALAPPDATA% (found in the 0.10.3 bundle drill).

    Fixed¶

    • heronry update from the desktop app's install works again: 0.10.2's update helper died at its first import (No module named 'update_lock') because the bundle ran it without its own folder on the import path, and the command still said "handed over", so nothing was installed and nothing said why. The bundle now runs a script as python does, and the helper adds its folder itself. This is why the hop from 0.10.2 is by hand.
    • heronry update watches the update helper start before it hands over; a helper that ends without a result is reported in the shell with its own error, and nothing was changed.

    0.10.0¶

    Added¶

    • Guest sharing: a guest role with per-epic membership. Every read a guest makes is scoped to the epics they are in, actions outside their authority are refused, and live secrets are screened out of every guest-visible view.
    • An asks ledger. An ask clears when it is really dealt with: another seat answers it, a later message on the ticket settles it, or the ticket moves past it. A criterion whose checker seat closed gets a fresh checker, and "Needs you" shows only what no live seat can act on.
    • Update in place, one path for the command line and the tray: seats are parked, the services stopped, the new release installed, and the seats resumed, with rollback on failure. A seat that fails to park, a stop that leaves the board answering, or a seat that fails to resume is never reported as a plain success.
    • Learning: lessons carry a scope, can be backfilled and retired, and the architect reads them before designing.
    • The desktop shell: notifications, quoting, links and Back/Forward.
    • Web and VS Code: $ artifact mentions, topic page parity, and a Code tab that needs no npm (Windows x64 downloads the pinned code-server and checks its sha256).
    • Upgrading merges the new pool settings.json template into an existing install once. It adds the compact SessionStart hook and drops the retired effortLevel pin, and every value the owner set is kept.

    Changed¶

    • Model and effort: a seat's Claude effort is real (it rides the launch arguments) and is capped at high in the board and the pool, and each role gets its own option lists.
    • Less waste per seat: heartbeats come through the feed driver, boots are lean, and tool output is capped.
    • A precision pass over the guides, role cards and tool definitions.
    • ticket_read with no include returns a compact read: the record, criteria, docs, the words header, the 3 newest messages, and counts of the rest; more names the full read.
    • Repeated sibling headings get an occurrence selector (# Manual > ## Example ⟨2⟩). A heading's literal text is always matched first.
    • For agents, /v1/docs/{id}/html returns the rendered head plus doc_read's continuation; people keep the whole page.
    • Summary-first docs (S17): doc_read(id) returns the first page, a heading map with each section's size and a continuation, then sections or pages; the whole body (all=true) is an HTTP read for the web and VS Code views only. Every doc write tool points to the new /doc-write skill. Docs written before this change carry layout=legacy, and every read of one says "not structured for easy read; consider rewriting summary-first"; doc_update(layout="summary_first") clears it.
    • find searches docs by section (a heading's own text; long or heading-less text by paragraph), so a term anywhere in a long doc is found and embedded; a doc hit names its section, ready for doc_read(section=). The search table is rebuilt once on first start.
    • doc_read(section=) returns the section's own text, up to its first subsection, plus each direct subsection's heading and size; include_children=true returns the whole subtree. A range read's reply drops empty fields.
    • ticket_read and context list the epic's strategy/domain docs and their extends parents.
