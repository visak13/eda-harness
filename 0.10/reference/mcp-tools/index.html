    MCP tools¶

    Generated at build from the tool definitions every seat's MCP server advertises (72 tools). A seat sees only its role's bundle; the roles line lists the built-in roles that get each tool (a custom workflow role picks its own in the Design tab).

    Each tool lists its input, the arguments it takes, and its output. Every tool replies with the same wrapper:

    Field Meaning
    ok true when the call worked, false when it was refused or failed
    value the result, present when ok is true; its shape is described under each tool
    error present when ok is false: a code, a message, and for a bad argument the field and what it accepts
    hint one line on what to do next

    The examples are real replies, captured by calling each tool on a throwaway board seeded with a made-up project (the one in Using Heronry). Long lists and text are shortened.

    artifact · board · close · doc · doctor · framework · identity · knowledge · pool · search · thread · ticket

    artifact¶

    artifact_create¶

    Record a produced thing by uri, optionally linked to a ticket.

    When: when you ship something the owner should see

    Input

    Argument Type Required Meaning
    idempotency_key string Optional retry key. The same key with the same arguments within 24 hours returns the first artifact instead of a second one, and the same key with different arguments is refused as a conflict; without a key, an identical create by the same seat within 10 minutes is replayed.
    form one of image, file, url, app, repo_ref yes What kind of thing the artifact is: image, file, url, app or repo_ref.
    uri string yes Where the artifact lives, as a URI such as a web link or a repository reference. Pass a URI, never a local machine path; the board stores it as given.
    note string Optional; defaults to an empty string. A short caption shown with the artifact.
    ticket_id string Optional. A ticket id to link the artifact to with a produced link, so it shows on that ticket. When omitted, the artifact is created unlinked.

    Output

    the artifact.

    Example: called by the engineer

    Input:

    {
  "form": "url",
  "uri": "https://ci.example.com/tidewater/builds/412",
  "note": "CI run for the merge change",
  "ticket_id": "s-96480e4e94"
}

    Output:

    {
  "ok": true,
  "value": {
    "id": "art-2ac139f3d2",
    "created_at": "2026-10-04T22:12:55.368898Z",
    "created_by": "engineer.s-96480e4e94",
    "form": "url",
    "uri": "https://ci.example.com/tidewater/builds/412",
    "note": "CI run for the merge change",
    "staged": false,
    "content_type": "",
    "filename": ""
  },
  "hint": ""
}

    Roles: adversary, architect, engineer

    artifact_upload¶

    Stage a workspace file (25 MB cap) as an artifact.

    When: to attach a local file

    Input

    Argument Type Required Meaning

    events_query¶

    Read the event log by subject or since a seq.

    When: to reconstruct or catch up on events

    Input

    Argument Type Required Meaning
    limit integer Optional; defaults to 25. Events per page, clamped to 1 to 100; a compact page is also cut to about 8 KB.
    cursor string Optional. The next_cursor from the previous page, passed with the same filters; it takes the place of since. A cursor from a different query is refused.
    verbose boolean Optional; defaults to false. When true, returns full event rows instead of compact ones with clipped data.
    subject_id string Optional. Only events whose subject is this id, such as a ticket, doc or ask. When omitted, all events you may see are returned.
    since integer Optional; defaults to 0. Return only events with a sequence number after this one; 0 starts from the beginning. Pass the last last_seq to catch up.

    matching events, a ≤8 KB page from since + last_seq, next_cursor.

    doc¶

    doc_create¶

    Author a versioned markdown doc.

    When: to record a design, strategy, domain guide, report or note (/doc-write)

    Input

    Argument Type Required Meaning
    idempotency_key string Optional retry key. The same key with the same arguments within 24 hours returns the first doc instead of a second one, and the same key with different arguments is refused as a conflict; without a key, an identical create by the same seat within 10 minutes is replayed.
    doc_type one of design, strategy_hl, strategy_ll, domain, report, note yes The kind of doc: design, strategy_hl, strategy_ll, domain, report or note. Each type has its authors in the workflow (design: architect; strategy and domain: sme; report: engineer, adversary or qa; note: any role); anyone else must file it with status set to proposed.
    title string yes The doc's title.
    body_md string The doc's body as Markdown (pass this or its alias body). Put the summary first; readers get the first page and a heading map by default.
    body string Optional alias of body_md; pass one of the two. The call is refused when neither is given.
    scope string yes Where the doc applies: an epic id, domain:<name> or global.
    tags list of string Optional. Knowledge tags for the doc, normalized by the board. When omitted, the doc has no tags.
    status one of active, proposed Optional; defaults to active. proposed files a suggestion that the owner approves or rejects in the Library, and lets a role that is not an author of this doc type file it.
    proposes string Optional, only with status set to proposed. The id of the active doc of the same type that this proposal would become the next version of.
    ticket_id string Optional. The ticket the doc came from; the board records it as the source of a proposed doc. It does not link the doc to the ticket, so use link_create for that.

    Output

    a receipt; link it to its ticket.

    Example: called by the engineer

    Input:

    {
  "doc_type": "report",
  "scope": "s-96480e4e94",
  "title": "S2 evidence: merge replay",
  "body_md": "# S2 evidence\n\nTwo devices, 200 offline edits each, replayed in both orders.\nNo paragraph lost.\n"
}

    Output:

    {
  "ok": true,
  "value": {
    "id": "report-950fead95b",
    "created_at": "2026-10-04T22:12:55.173658Z",
    "created_by": "engineer.s-96480e4e94",
    "doc_type": "report",
    "title": "S2 evidence: merge replay",
    "body_md": "# S2 evidence\n\nTwo devices, 200 offline edits each, replayed in both orders.\nNo paragraph lost.\n",
    "version": 1,
    "owner_role": "engineer",
    "scope": "s-96480e4e94",
    "status": "active",
    "layout": "summary_first"
  },
  "hint": "link it: link_create(from_id=<ticket>, to_id=<doc>, relation=designed_by|uses_strategy|uses_domain|evidence_for). write docs summary-first: the /doc-write skill"
}

    Roles: adversary, architect, engineer, qa, sme

    doc_edit¶

    Like Edit: exact unique old_string->new_string or non-overlapping edits; apply atomically against 1 version.

    When: for small revisions after doc_read; expected_version defaults to your last read (/doc-write)

    Input

    Argument Type Required Meaning
    expected_version integer Optional. The doc version you read (1 or higher); when omitted, the version last served to you. If the doc has moved on, the edit is refused as a version conflict and you must read it again.
    edits list of object Optional when old_string and new_string are given. From 1 to 100 pairs of old_string and new_string (old_text and new_text also work). Each old_text must occur exactly once in the original body and the edits must not overlap; all edits apply together as one new version, or none apply.
    title string Optional. A new title for the doc. When omitted, the title stays as it is.
    id string yes The doc id to edit. You must be an author of its doc type or have the role that owns it.
    old_string string The text to replace, copied exactly from the doc body. It must occur exactly once unless replace_all is true. Use this with new_string for a single edit, or use edits for several, not both.
    new_string string The text that replaces old_string. An empty string deletes the match.
    replace_all boolean Optional; defaults to false. When true, every occurrence of old_string is replaced instead of requiring exactly one.

    Output

    a compact receipt, or a conflict/match error (re-read).

    Example: called by the engineer

    Input:

    {
  "id": "report-5f5e696100",
  "old_string": "No paragraph lost.",
  "new_string": "No paragraph lost; 3 conflicts surfaced, all same-paragraph."
}

    Output:

    {
  "ok": true,
  "value": {
    "id": "report-5f5e696100",
    "version": 2,
    "changed_fields": [
      "body_md"
    ],
    "layout": "summary_first",
    "read_ref": {
      "tool": "doc_read",
      "id": "report-5f5e696100",
      "version": 2
    }
  },
  "hint": "doc_read(id, version) for the resulting body"
}

    Roles: adversary, architect, engineer, qa, sme

    doc_read¶

    Read a doc head-first: page 1 is the writer's unchecked summary; obligations may sit in sections.

    When: when a ticket or link points at a doc; head first, then whole or sections (/doc-read)

    work_type one of feature, bug, rnd, creative, review, knowledge, chore yes The kind of work: feature, bug, rnd, creative, review, knowledge or chore.
    title string yes For an epic, the owner's words verbatim (a short title is derived when they run past 80 characters). For a story or task, the name of the slice. Must not be blank.
    words string Optional. For an epic or an owner's quick task, the owner's request verbatim; it never changes after create. When omitted on an epic, title is stored as the words; other tickets ignore it.
    parent_id string The parent ticket: an epic for a story, a story for a task. Required for both, except the owner's story with no parent, which becomes a quick task tagged quick. A story over the epic's 8-open-story cap is refused unless cap_lift_message is passed; a sixth task in a story is created with a hint that a story normally holds five.
    assignee string Optional. The participant id to assign the ticket to at create. When omitted, the ticket starts unassigned.
    description string Optional; defaults to an empty string. The scope, intent and pointers to files or docs.
    tags list of string Optional. Tags for the ticket. Only the owner may use quick, and help is reserved for help threads; sme:on, sme:off and project:<key> are checked as epic policy tags.
    serves list of string Advice only. A task should name what it serves; without it the task is created anyway with a hint, and on any other kind it is ignored with a hint. The requirement ids from requirements, or ids of finding messages, on the same epic that the task serves.
    cap_lift_message string Optional. The id of the owner's reply in chat that lifts the story cap on this epic. The board checks that it is a message of the epic's owner; any other message is refused. Without it, a story over the cap is refused.

    ticket_query¶

    When: to find tickets without an id

    Input

    verbose boolean Optional; defaults to false. When true, returns full rows instead of compact ones, still paged but without the 8 KB fit.
    kind one of epic, story, task Optional. Only tickets of this level: epic, story or task.

    ticket_update¶

    Change the args given, per the transition rules.

    When: to move or assign a ticket; in_review only once verified

    Input

    Argument Type Required Meaning
    ticket_id string yes The ticket to change; id is accepted as another name for it. Only the arguments you pass are changed.
    status one of drafted, designed, signed_off, ready, in_progress, in_review, blocked, done, partial, dropped Optional. The status to move to: drafted, designed, signed_off, ready, in_progress, in_review, blocked, done, partial or dropped. The board refuses a transition the epic's workflow does not allow and names what is missing.
    assignee string Optional. The participant id to assign. The workflow decides who may assign (the architect or the owner, and an engineer for its own tasks), and a checker of the ticket's criteria cannot become its doer.
    design_ref string Optional. The id of the design or plan doc (a design, report or note doc). The architect sets it on epics and stories, the engineer on tasks; on an epic it can carry the epic to designed.
