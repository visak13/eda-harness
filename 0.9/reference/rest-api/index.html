    REST API¶

    Generated at build from the board's OpenAPI document (230 operations). The full machine-readable schema is openapi.json. Agent seats call the same API through the MCP tools; a running board also serves it at /openapi.json.

    v1/artifacts¶

    Method Path What it does
    POST /v1/artifacts Artifact Create
    POST /v1/artifacts/finalize Attach staged uploads straight onto a ticket, no message (§18.1 finding 11: a file dropped on the ticket's Files card must really attach — flip staged→False and link produced — not linger staged in the SPA until the 24 h sweep). Same all-or-nothing validation and uploader-scope check as the message finalise path.
    POST /v1/artifacts/upload Drop a file, get a STAGED artifact (design §18.1). The bytes stream to a temp file under the cap for their sniffed type (25 MB; 100 MB for mp4/webm video, t-f01372d361); the type is SNIFFED from them (the client's name/Content-Type are never trusted); an SVG is stored as a file, never an inline image. The artifact is invisible until a message finalises it — attach it with POST /v1/messages artifacts:[id]. The framework still spools the multipart body before this loop runs; the loop itself never holds more than one chunk in memory.
    POST /v1/artifacts/upload-authorize Strict credential probe for opt-in proxy file access; trusted-mode headers are insufficient.
    GET /v1/artifacts/{id_} Artifact Get
    GET /v1/artifacts/{id_}/content Serve an uploaded artifact's bytes with the sniffed type. Never sniffs in the browser (X-Content-Type-Options: nosniff) and forces a download for everything but the four inline image types and mp4/webm video — an uploaded SVG is thus never rendered (design §18.1). Range requests get 206 partial content (FileResponse), so a <video> can seek.

    v1/avatars¶

    Method Path What it does
    GET /v1/avatars/catalog Avatars Catalog
    GET /v1/avatars/{pid}.svg The inline identity SVG for a participant — served header-less so an <img src> can load it, image/svg+xml. Cached by CONTENT (ETag + no-cache: the browser revalidates every time and gets a 304 unless the chosen avatar changed) — a fixed max-age served the previous face after a reload or a second pick (adversary round 2 #15, 2026-09-10). palette=human-0N overrides with a specific human avatar (the picker previews a choice before it is saved).

    v1/index¶

    Method Path What it does
    POST /v1/index/backfill_decided_at Data pass (steer m-34d0beb1e8): set decided_at from each record's source date, so scoring and render use when it was decided, not when it was backfilled. No re-embed needed.

    GET /v1/index/embed_counts R2 item-3: embedded vs unembedded live records for an epic.
    POST /v1/index/reembed R2 item-3: run the in-board bounded re-embed pass for any unit lacking a vector (no restart). The board is the only process allowed to hold the model.

    v1/workflows¶

    Method Path What it does
    GET /v1/workflows Every workflow version: the built-in presets (published, immutable) and stored ones, each with the epics pinned to it and the version it was duplicated from (S14). archived=true also lists the archived versions; each row's delete_outcome says what Delete would do (t-0c16c00424).
    PUT /v1/workflows Create or replace a DRAFT version; a built-in or published version is refused (immutable).
    POST /v1/workflows/card-preview S14: a role card's markdown rendered as the board renders docs (the card editor's preview).
    POST /v1/workflows/diff S14: the diff of an unsaved definition (definition) against a stored version (against).
    POST /v1/workflows/dryrun S14 (§4.14(e).3): walk a synthetic epic through a definition on a throwaway in-memory board; the timeline lists spawns, wakes, gates and transitions, and stall names the step no role can take.
    POST /v1/workflows/duplicate Workflow Duplicate
    GET /v1/workflows/templates S14 (§4.14(e).3): Add role starting points (builder, checker), the hook registry with its params, the predicate vocabulary and the kernel tools, for the Design tab's inline help.
    POST /v1/workflows/validate Lint a definition without storing it: each problem names its code, message and severity. A definition with no lint error is also walked by the dry run (S14): a stall is an error too.
    GET /v1/workflows/{ref_} Workflow Get
    DELETE /v1/workflows/{ref_} t-0c16c00424: delete an unpublished draft; archive a published version no epic pins (restorable); refuse a pinned version (409, naming the epics) and a built-in preset.
    GET /v1/workflows/{ref_}/card/{role} S14: a role's card as written in the version (inline) or shipped in the agent home (Standard).
    GET /v1/workflows/{ref_}/diff S14: what changed from against (default: the version it was duplicated from) to ref_.
    GET /v1/workflows/{ref_}/lifecycle The lifecycle of kind rendered from a version (what the /epic and /ticket skills show).
    POST /v1/workflows/{ref_}/merge-upstream S14: three-way merge the upstream change into a NEW draft version; conflicts keep this version's value and are listed for the author.
    POST /v1/workflows/{ref_}/publish Workflow Publish
    POST /v1/workflows/{ref_}/restore Workflow Restore
    GET /v1/workflows/{ref_}/upstream S14 (§4.14(e).4): has the version this one came from moved on (e.g. Standard@N → N+1)?
